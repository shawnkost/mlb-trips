## Project

- Single Next.js app at the repo root with no separate backend; DB schema and migrations live in `db/` (Drizzle). `docker-compose.yml` only provides the local dev Postgres (see README).
- `db/auth-schema.ts` is generated by the Better Auth CLI from `lib/auth.ts` via the CLI-only entry `lib/auth-cli.ts` (`npx auth generate --config lib/auth-cli.ts --output db/auth-schema.ts`, needs `DATABASE_URL`); regenerate it instead of hand-editing, then run `npm run db:generate`.
- Server Actions live in `app/**/actions.ts` and stay thin: `(prevState, formData)` returning `ActionResult` from `lib/actions/result.ts` (`{ ok, data } | { fieldErrors } | { error }`) for `useActionState`. Wrap the body in `runAction` (`lib/actions/server.ts`) so the session is re-checked first and unexpected errors become `{ error }`; validate with the shared zod schemas in `lib/validation/` (visit input via `parseVisitInput`, which also rejects unknown parks); call the DAL, which selects explicit DTO columns (see `parkColumns` in `lib/dal/parks.ts`), never raw rows. Client forms wrap the action in `withStaleActionRetry` (`lib/actions/client.ts`) so post-deploy "Failed to find Server Action" errors show "refresh and retry".
- Validate with `npm run lint && npm run typecheck && npm run format:check && npm test && npm run test:integration && npm run build` (scripts in `package.json`; integration tests need the compose Postgres, see README "Tests").
